## 0.1 0단계에서 배우는 것

0단계에서는 코드를 먼저 작성하지 않는다.  
주니어는 먼저 **프로젝트 기준선**을 정리하는 방법을 배운다.

프로젝트 기준선은 앞으로 개발할 프로젝트가 흔들리지 않도록 미리 정해두는 출발 기준이다.

쉽게 말하면 다음과 같다.
```text
프로젝트 기준선 = 개발을 시작하기 전에 정하는 프로젝트의 목적, 범위, 데이터, 구조, 산출물 기준
```

AI 네이티브 데이터 플랫폼 프로젝트는 단순히 API나 DB를 먼저 만든다고 완성되지 않는다.  
센서 데이터, 전력 데이터, 작업자 위치 데이터, AI 로그, RAG 로그, 피드백 데이터가 서로 연결되기 때문에 개발 전에 전체 흐름을 먼저 정리해야 한다.

0단계에서 주니어는 다음 질문에 답할 수 있어야 한다.
```text
이 프로젝트는 무엇을 해결하려는가?
누가 사용하는가?
어떤 데이터가 발생하는가?
그 데이터는 어디서 들어오는가?
어떤 사건을 이벤트로 남길 것인가?
Raw, Staging, Mart는 어떻게 구분할 것인가?
AI 학습 데이터, RAG 로그, 피드백 데이터는 어디서 만들어지는가?
이번 프로젝트에서 만들 것과 만들지 않을 것은 무엇인가?
파일명, 이벤트명, 테이블명, 브랜치명은 어떤 규칙으로 정할 것인가?
최종적으로 어떤 산출물을 남겨야 하는가?
```

따라서 0단계는 기능 구현 단계가 아니다.  
0단계는 이후 1~7단계 개발이 흔들리지 않도록 **프로젝트의 기준 언어와 기준 구조를 맞추는 단계**이다.

산업안전 관제 플랫폼 실습에서는 다음 데이터가 어떤 흐름으로 연결되는지 기준선을 작성한다.
```text
유해가스 센서 데이터
스마트 파워 전력 데이터
작업자 위치 데이터
위험구역 데이터
알람 데이터
AI 판단 결과 데이터
RAG 대응 매뉴얼 데이터
운영자 피드백 데이터
```

## 0.2 전체 과정에서 0단계의 위치

0단계는 전체 과정의 출발점이다.
```text
0단계: 프로젝트 기준선 정리
→ 1단계: AI 서비스와 데이터 플랫폼 아키텍처
→ 2단계: AI 데이터 수집과 레이크하우스 설계
→ 3단계: AI 워크로드를 위한 데이터 파이프라인 자동화
→ 4단계: 대용량 로그와 실시간 이벤트 스트리밍
→ 5단계: AI 데이터 품질, 계보, 거버넌스
→ 6단계: RAG와 벡터 데이터 파이프라인
→ 7단계: AI 서비스 피드백 데이터와 DataOps 운영
```

1단계에서는 AI 서비스와 데이터 플랫폼의 전체 아키텍처를 설계한다.  
하지만 그 전에 0단계에서 프로젝트 목적, 데이터 소스, 이벤트, 시스템 경계, 산출물 기준이 먼저 정리되어 있어야 한다.

0단계에서 작성한 산출물은 이후 단계에서 계속 사용된다.

| 0단계 산출물 | 이후 연결 단계 |
|---|---|
| 프로젝트 목적 | 1단계 아키텍처 설명 기준 |
| 데이터 소스 맵 | 1단계 데이터 플랫폼 구조, 2단계 Collector API 기준 |
| 도메인 이벤트 맵 | 1단계 이벤트 설계, 2단계 Schema/샘플 JSON 기준 |
| 데이터 계약 후보 | 2단계 Data Contract, Pydantic, JSON Schema 기준 |
| Raw/Staging/Mart 흐름 | 2단계 Lakehouse, 3단계 Pipeline 기준 |
| 시스템 경계 | 전체 단계의 구현 범위 기준 |
| 컨벤션 | 파일명, 브랜치명, 이벤트명, 테이블명 기준 |
| 최종 시연 시나리오 | 프로젝트 발표와 포트폴리오 기준 |
| 완료 체크리스트 | 단계별 산출물 검토 기준 |

0단계가 없으면 이후 단계에서 다음 문제가 생길 수 있다.
```text
프로젝트 목적이 흔들린다.
같은 데이터를 서로 다른 이름으로 부른다.
이벤트명과 파일명이 연결되지 않는다.
Raw, Staging, Mart 기준이 모호해진다.
무엇을 만들고 무엇을 제외할지 정해지지 않는다.
GitHub 브랜치와 산출물 기준이 흐트러진다.
```

그래서 0단계는 단순한 준비 시간이 아니다.  
0단계는 전체 수업의 방향을 고정하는 기준선 작성 단계이다.

## 0.3 0단계 핵심 질문

0단계의 핵심 질문은 다음과 같다.
```text
AI 네이티브 데이터 플랫폼을 만들기 전에,
프로젝트 목적, 데이터 소스, 이벤트, 데이터 흐름, 시스템 경계, 산출물 기준을
어떻게 정리해야 이후 개발이 흔들리지 않는가?
```

이 질문을 다음 관점으로 나누어 학습한다.
```text
목적 관점:
이 프로젝트는 어떤 문제를 해결하려는가?

도메인 관점:
프로젝트가 다루는 업무 세계는 무엇인가?

사용자 관점:
누가 이 시스템을 사용하고, 누가 데이터를 생성하는가?

데이터 관점:
어떤 데이터가 발생하고, 어떤 형식으로 들어오는가?

이벤트 관점:
업무에서 발생하는 중요한 사건을 어떤 이벤트명으로 남길 것인가?

데이터 흐름 관점:
데이터는 수집 후 Raw, Staging, Mart, AI/RAG/피드백으로 어떻게 이동하는가?

범위 관점:
이번 프로젝트에서 만들 것과 만들지 않을 것은 무엇인가?

컨벤션 관점:
파일명, 이벤트명, 테이블명, API 경로, 브랜치명은 어떤 규칙을 따를 것인가?

산출물 관점:
0단계가 끝났을 때 어떤 문서, 샘플 데이터, 체크리스트가 남아야 하는가?
```


## 0.10 세부 로드맵

### 1일차. 프로젝트 기준선과 데이터 소스 이해 — 8h

#### 학습 목표

주니어는 프로젝트 기준선이 무엇인지 이해하고, 산업안전 관제 플랫폼의 목적과 데이터 소스를 정리할 수 있어야 한다.

이론 3h

## 0.12 0단계 완료 기준

0단계는 다음 기준을 만족하면 완료로 본다.
```text
프로젝트 목적을 한 문장으로 설명할 수 있다.
데이터 소스 5개 이상을 정리했다.
도메인 이벤트 5개 이상을 정의했다.
정상 샘플 JSON과 오류 샘플 JSON을 구분했다.
Raw, Staging, Mart 흐름을 설명할 수 있다.
AI 학습 데이터, RAG 로그, 피드백 데이터를 구분할 수 있다.
만드는 것과 만들지 않는 것을 문서로 작성했다.
컨벤션에 맞는 파일명과 이벤트명을 사용했다.
GitHub 기준선 산출물 위치를 이해했다.
최종 시연 시나리오와 완료 체크리스트를 작성했다.
```

0단계가 끝났을 때 주니어는 다음 질문에 답할 수 있어야 한다.
```text
왜 이 프로젝트를 만드는가?
어떤 데이터가 들어오는가?
그 데이터는 어떤 이벤트로 표현되는가?
정상 데이터와 오류 데이터는 어떻게 구분할 것인가?
Raw, Staging, Mart는 각각 어떤 역할을 하는가?
AI, RAG, 피드백 데이터는 어디에서 만들어지는가?
이번 수업에서 실제로 만들지 않는 것은 무엇인가?
내가 작성한 산출물은 GitHub 어디에 있는가?
```

## 0.13 1단계로 넘겨야 할 기준

0단계 산출물은 1단계 아키텍처 설계의 입력이 된다.

1단계로 넘어가기 전에 다음이 준비되어 있어야 한다.
```text
프로젝트 목적
사용자 역할
데이터 소스
이벤트 후보
AI 서비스 데이터 유형
RAG 문서 데이터 유형
피드백 데이터 유형
Raw / Staging / Mart 기준 흐름
시스템 경계
최종 시연 목표
```

1단계에서는 이 내용을 바탕으로 다음을 만든다.
```text
AI 서비스와 데이터 플랫폼 전체 아키텍처
C4 Context 다이어그램
C4 Container 다이어그램
서비스별 역할 정의
API 후보 목록
이후 2~7단계 개발 범위 연결표
```

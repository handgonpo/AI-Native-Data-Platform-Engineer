# 오류 주문 JSON의 처리 순서

오류 주문 데이터는 Pydantic 데이터 계약 검증에서 실패한 뒤, 원본 데이터와 오류 내용을 `Dead Letter JSONL`에 저장하고 사용자에게 `422 Unprocessable Entity` 응답을 반환합니다.

전체 흐름은 다음과 같습니다.
```text
오류 Sample JSON
→ curl 또는 Swagger가 HTTP POST 전송
→ collect.py가 요청 수신
→ events.py의 Pydantic 데이터 계약 검증
→ ValidationError 발생
→ collect.py의 except 실행
→ ingest.py의 save_order_dead_letter() 호출
→ Dead Letter 레코드 구성
→ config.py의 Dead Letter 경로 참조
→ lakehouse.py의 append_jsonl() 호출
→ Dead Letter JSONL 저장
→ 저장 경로 반환
→ HTTPException으로 422 오류 응답
```

---

## ① 오류 Sample JSON 준비

```text
sample_events/order_created.invalid.sample.json
```

이 파일은 Pydantic 데이터 계약을 일부러 위반하도록 작성한 테스트 입력값입니다.

```json
{
  "event_id": "evt-order-002",
  "event_type": "order_created",
  "schema_version": "1.0.0",
  "source_system": "shopping_mall",
  "event_time": "2026-07-21T13:05:00+09:00",
  "payload": {
    "order_id": "",
    "customer_id": "USER-002",
    "total_amount": -5000,
    "currency": "KRW",
    "item_count": 0
  }
}
```

검증 실패가 예상되는 값은 다음과 같습니다.

```text
order_id = ""
→ 최소 한 글자 이상이어야 하는 조건 위반

total_amount = -5000
→ 0 이상이어야 하는 조건 위반

item_count = 0
→ 1 이상이어야 하는 조건 위반
```

이 JSON 파일이 스스로 실행되는 것은 아닙니다.

---

## ② curl 또는 Swagger가 HTTP 요청 전송

curl을 사용하는 경우:

```bash
curl -X POST \
  "http://127.0.0.1:8001/api/collect/order" \
  -H "Content-Type: application/json" \
  -d @sample_events/order_created.invalid.sample.json
```

처리 흐름:

```text
오류 Sample JSON 읽기
→ HTTP Request Body에 넣기
→ POST /api/collect/order로 전송
```

Swagger를 사용하는 경우에도 동일한 Endpoint로 JSON 요청을 전송합니다.

---

## ③ `collector/routes/collect.py`가 요청 수신

다음 Endpoint 함수가 실행됩니다.

```python
def collect_order_event(
    raw_body: dict[str, Any]
):
```

FastAPI는 HTTP 요청 본문의 JSON을 Python 딕셔너리로 변환하여 `raw_body`에 전달합니다.

```text
HTTP JSON
→ Python dict
→ raw_body
```

이 시점의 `raw_body`에는 아직 검증되지 않은 원본 요청이 들어 있습니다.

---

## ④ `collector/schemas/events.py`의 데이터 계약으로 검증

`collect.py`의 `try` 블록에서 다음 코드가 실행됩니다.

```python
event = OrderCreatedEvent.model_validate(
    raw_body
)
```

연결 흐름:

```text
collector/routes/collect.py
↓
collector/schemas/events.py
```

검증 대상:

```text
OrderCreatedEvent
├── event_id
├── event_type
├── schema_version
├── source_system
├── event_time
└── payload: OrderPayload
    ├── order_id
    ├── customer_id
    ├── total_amount
    ├── currency
    └── item_count
```

오류 JSON은 데이터 계약을 위반하므로 Pydantic이 `ValidationError`를 발생시킵니다.

```text
OrderCreatedEvent.model_validate(raw_body)
↓
검증 실패
↓
ValidationError 발생
```

검증에 실패했기 때문에 정상적인 `OrderCreatedEvent` 객체는 만들어지지 않습니다.

---

## ⑤ `collector/routes/collect.py`의 `except` 실행

발생한 `ValidationError`는 다음 코드에서 잡힙니다.

```python
except ValidationError as error:
```

흐름:

```text
try에서 ValidationError 발생
↓
except ValidationError as error 실행
```

이제 `error` 객체에는 어떤 필드가 어떤 이유로 실패했는지에 대한 정보가 들어 있습니다.

```python
error.errors()
```

예시:

```json
[
  {
    "type": "string_too_short",
    "loc": ["payload", "order_id"],
    "msg": "String should have at least 1 character"
  },
  {
    "type": "greater_than_equal",
    "loc": ["payload", "total_amount"],
    "msg": "Input should be greater than or equal to 0"
  },
  {
    "type": "greater_than_equal",
    "loc": ["payload", "item_count"],
    "msg": "Input should be greater than or equal to 1"
  }
]
```

---

## ⑥ `collector/services/ingest.py`의 오류 저장 함수 호출

`collect.py`의 `except` 블록에서 다음 함수를 호출합니다.
```python
dead_letter_path = save_order_dead_letter(
    raw_body=raw_body,
    errors=error.errors()
)
```

연결 흐름:
```text
collector/routes/collect.py
↓
collector/services/ingest.py
↓
save_order_dead_letter()
```

전달되는 값은 다음 두 가지입니다.

| 전달값 | 의미 |
|---|---|
| `raw_body` | API로 들어온 검증 전 원본 JSON |
| `errors` | Pydantic이 찾아낸 검증 오류 목록 |

---

## ⑦ Dead Letter에 저장할 레코드 구성

`save_order_dead_letter()` 안에서 다음 딕셔너리를 만듭니다.
```python
dead_letter_record = {
    "failed_at": datetime.now(
        timezone.utc
    ).isoformat(),
    "dataset": "order_events",
    "raw_body": raw_body,
    "errors": errors
}
```

Dead Letter 레코드는 단순히 오류 JSON만 저장하지 않습니다.

```text
failed_at
→ 언제 검증에 실패했는가?

dataset
→ 어떤 데이터셋에서 실패했는가?

raw_body
→ API로 들어온 원본 요청은 무엇인가?

errors
→ 어떤 필드가 어떤 이유로 실패했는가?
```

구성 결과 예시:

```json
{
  "failed_at": "2026-07-11T03:05:04.355678+00:00",
  "dataset": "order_events",
  "raw_body": {
    "event_id": "evt-order-002",
    "event_type": "order_created",
    "schema_version": "1.0.0",
    "source_system": "shopping_mall",
    "event_time": "2026-07-21T13:05:00+09:00",
    "payload": {
      "order_id": "",
      "customer_id": "USER-002",
      "total_amount": -5000,
      "currency": "KRW",
      "item_count": 0
    }
  },
  "errors": [
    {
      "loc": ["payload", "order_id"],
      "msg": "String should have at least 1 character"
    }
  ]
}
```

## ⑧ `collector/core/config.py`의 저장 경로 참조

`ingest.py`는 서버가 시작될 때 import해 둔 다음 경로 상수를 사용합니다.

```python
DEAD_LETTER_ORDER_FILE
```

실제 경로:

```text
data_lake/dead_letter/order_events/order_events_errors.jsonl
```

정확한 관계는 다음과 같습니다.

```text
ingest.py
- - - → config.py의 DEAD_LETTER_ORDER_FILE 참조
```

이 단계에서 `config.py`의 함수가 새로 실행되는 것은 아닙니다.

`config.py`는 저장 위치를 알려주는 역할이고, 실제 파일 저장은 `lakehouse.py`가 담당합니다.

---

## ⑨ `collector/core/lakehouse.py`의 공통 저장 함수 호출

`save_order_dead_letter()` 안에서 다음 코드가 실행됩니다.

```python
append_jsonl(
    file_path=DEAD_LETTER_ORDER_FILE,
    record=dead_letter_record
)
```

연결 흐름:

```text
collector/services/ingest.py
↓
collector/core/lakehouse.py
↓
append_jsonl()
```

전달값:

| 전달값 | 내용 |
|---|---|
| `file_path` | Dead Letter JSONL 저장 경로 |
| `record` | 원본 요청과 오류 정보를 합친 Dead Letter 레코드 |

## ⑩ Dead Letter JSONL 파일에 한 줄 추가

`append_jsonl()` 함수가 실제 파일 저장을 수행합니다.

```python
def append_jsonl(
    file_path: Path,
    record: dict[str, Any]
) -> None:
```

내부 처리 순서:

```text
file_path.parent 확인
↓
저장 폴더가 없으면 생성
↓
JSONL 파일을 "a" 모드로 열기
↓
dead_letter_record를 JSON 문자열로 변환
↓
파일 마지막에 한 줄 추가
↓
줄바꿈 "\n" 추가
```

저장 위치:

```text
data_lake/dead_letter/order_events/order_events_errors.jsonl
```

저장 결과 예시:

```json
{"failed_at":"2026-07-11T03:05:04.355678+00:00","dataset":"order_events","raw_body":{"event_id":"evt-order-002","event_type":"order_created","schema_version":"1.0.0","source_system":"shopping_mall","event_time":"2026-07-21T13:05:00+09:00","payload":{"order_id":"","customer_id":"USER-002","total_amount":-5000,"currency":"KRW","item_count":0}},"errors":[{"loc":["payload","order_id"],"msg":"String should have at least 1 character"}]}
```

오류 데이터는 Raw에 저장되지 않고 Dead Letter에만 저장됩니다.

---

## ⑪ 저장 결과가 역순으로 돌아감

저장이 끝나면 결과가 호출한 쪽으로 돌아갑니다.

```text
append_jsonl()
↓
반환값 없음: None

save_order_dead_letter()
↓
Dead Letter 파일 경로 문자열 반환

collect_order_event()
↓
dead_letter_path 변수에 저장
```

`ingest.py`:

```python
return str(
    DEAD_LETTER_ORDER_FILE
)
```

`collect.py`:

```python
dead_letter_path = save_order_dead_letter(
    raw_body=raw_body,
    errors=error.errors()
)
```

결과:

```text
dead_letter_path
=
data_lake/dead_letter/order_events/order_events_errors.jsonl
```

---

## ⑫ `collector/routes/collect.py`가 `HTTPException` 발생

Dead Letter 저장이 끝나면 `collect.py`에서 다음 코드가 실행됩니다.

```python
raise HTTPException(
    status_code=status.HTTP_422_UNPROCESSABLE_ENTITY,
    detail={
        "message": "주문 이벤트 검증 실패",
        "dead_letter_path": dead_letter_path,
        "errors": error.errors()
    }
) from error
```

여기서 `raise`가 실행되므로 함수는 즉시 중단됩니다.

따라서 아래의 정상 저장 코드는 실행되지 않습니다.

```python
saved_path = ingest_order_event(event)
```

정상 성공 응답도 실행되지 않습니다.

```python
return {
    "message": "주문 이벤트 저장 성공",
    ...
}
```

---

## ⑬ 사용자에게 `422 Unprocessable Entity` 응답

`HTTPException`은 FastAPI와 Uvicorn을 거쳐 요청을 보낸 사용자에게 전달됩니다.

```text
collector/routes/collect.py
↓
FastAPI
↓
Uvicorn
↓
curl 또는 Swagger
↓
422 Unprocessable Entity
```

예상 응답:

```json
{
  "detail": {
    "message": "주문 이벤트 검증 실패",
    "dead_letter_path": "data_lake/dead_letter/order_events/order_events_errors.jsonl",
    "errors": [
      {
        "type": "string_too_short",
        "loc": ["payload", "order_id"],
        "msg": "String should have at least 1 character"
      },
      {
        "type": "greater_than_equal",
        "loc": ["payload", "total_amount"],
        "msg": "Input should be greater than or equal to 0"
      },
      {
        "type": "greater_than_equal",
        "loc": ["payload", "item_count"],
        "msg": "Input should be greater than or equal to 1"
      }
    ]
  }
}
```

`@router.post()`에 다음 설정이 있어도:

```python
status_code=status.HTTP_201_CREATED
```

`201 Created`는 정상적으로 함수가 `return`했을 때만 적용됩니다.

이번에는 `HTTPException(422)`가 발생했으므로 최종 상태 코드는 `422`입니다.

# 파일별 최종 처리 순서

```text
① sample_events/order_created.invalid.sample.json
↓
② curl 또는 Swagger가 HTTP POST 전송
↓
③ collector/routes/collect.py
   collect_order_event(raw_body)
↓
④ collector/schemas/events.py
   OrderCreatedEvent.model_validate(raw_body)
↓
⑤ Pydantic ValidationError 발생
↓
⑥ collector/routes/collect.py의 except 실행
↓
⑦ collector/services/ingest.py
   save_order_dead_letter(raw_body, errors)
↓
⑧ dead_letter_record 구성
↓
⑨ collector/core/config.py의
   DEAD_LETTER_ORDER_FILE 경로 참조
↓
⑩ collector/core/lakehouse.py
   append_jsonl(...)
↓
⑪ data_lake/dead_letter/order_events/
   order_events_errors.jsonl 저장
↓
⑫ lakehouse.py → ingest.py → collect.py로
   Dead Letter 저장 경로 반환
↓
⑬ HTTPException(422) 발생
↓
⑭ curl 또는 Swagger에 422 오류 응답
```

# 정상 처리와 오류 처리의 분기점

```text
OrderCreatedEvent.model_validate(raw_body)
                ↓
        ┌───────┴────────┐
        │                │
     검증 성공         검증 실패
        │                │
ingest_order_event()  ValidationError
        │                │
     Raw 저장       save_order_dead_letter()
        │                │
  201 Created       Dead Letter 저장
                         │
                    422 응답
```

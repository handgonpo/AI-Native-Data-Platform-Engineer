> 권장 시수: 24시간

> 실습 도메인: 산업안전 관제 플랫폼

## 1.1 1단계에서 배우는 것

1단계에서는 AI 서비스가 단순히 모델 하나로 운영되지 않는다는 점을 배운다.

AI 서비스가 실제로 운영되려면 다음 요소가 함께 필요하다.

```text
데이터 수집
데이터 저장
데이터 검증
AI 추론
RAG 문서 검색
결과 저장
피드백 수집
데이터 품질 관리
운영 모니터링
```

따라서 1단계의 핵심은 **AI 서비스가 사용할 데이터와 그 데이터가 흐르는 시스템 구조를 먼저 설계하는 것**이다.

주니어는 1단계가 끝났을 때 다음 질문에 답할 수 있어야 한다.
```text
AI 서비스는 어떤 데이터를 필요로 하는가?
데이터 플랫폼은 AI 서비스에서 어떤 역할을 하는가?
데이터는 어디서 생성되어 어디로 이동하는가?
Raw, Staging, Mart는 왜 분리하는가?
Feature Dataset, Training Dataset, Vector DB는 어떤 역할을 하는가?
RAG 데이터는 센서 이벤트 데이터와 무엇이 다른가?
피드백 로그와 서비스 로그는 왜 운영 데이터이자 개선 데이터인가?
산업안전 관제 플랫폼에서는 이 구조가 어떻게 적용되는가?
```

산업안전 관제 플랫폼 실습에서는 다음 데이터가 전체 AI 데이터 플랫폼 안에서 어떻게 연결되는지 정의한다.
```text
가스 센서 데이터
전력 사용량 데이터
작업자 위치 데이터
알람 데이터
안전 매뉴얼 문서
AI 추론 결과
RAG 검색 로그
운영자 피드백
서비스 로그
```

## 1.2 전체 과정에서 1단계의 위치

1단계는 0단계에서 정리한 프로젝트 기준선을 실제 아키텍처 구조로 확장하는 단계이다.
```text
0단계: 프로젝트 기준선 정리
→ 1단계: AI 서비스와 데이터 플랫폼 아키텍처
→ 2단계: AI 데이터 수집과 레이크하우스 설계
→ 3단계: AI 워크로드를 위한 데이터 파이프라인 자동화
→ 4단계: 대용량 로그와 실시간 이벤트 스트리밍
→ 5단계: AI 데이터 품질, 계보, 거버넌스
→ 6단계: RAG와 벡터 데이터 파이프라인
→ 7단계: AI 서비스 피드백 데이터와 DataOps 운영
```

0단계에서 다음을 정리했다면,
```text
프로젝트 목적
데이터 소스
도메인 이벤트 후보
시스템 경계
기준 데이터 흐름
산출물 기준
```

1단계에서는 이것을 다음과 같은 아키텍처 산출물로 확장한다.
```text
AI 서비스 데이터 유형 맵
도메인 정의
데이터 소스 맵
Raw / Staging / Mart 역할 정의
도메인 이벤트 맵
이벤트 공통 필드
C4 Context 다이어그램
C4 Container 다이어그램
전체 데이터 흐름도
최종 시연 시나리오
```

즉, 1단계는 코드를 많이 작성하는 단계가 아니라, 이후 구현에서 사용할 **전체 구조와 데이터 흐름을 고정하는 단계**이다.

## 1.3 1단계 핵심 질문

1단계의 핵심 질문은 다음과 같다.
```text
AI 서비스가 신뢰할 수 있는 판단을 하려면,
데이터는 어떤 구조로 생성되고, 수집되고, 저장되고, 검증되고,
AI/RAG/대시보드/운영 피드백으로 연결되어야 하는가?
```

이 질문을 다음 관점으로 나누어 학습한다.
```text
데이터 발생 관점:
이 데이터는 어디서 생성되는가?

데이터 수집 관점:
이 데이터는 어떤 API, 파일, 로그, 이벤트로 들어오는가?

데이터 저장 관점:
Raw, Staging, Mart 중 어디에 저장되는가?

AI 활용 관점:
이 데이터는 학습, 추론, RAG, 피드백 중 어디에 쓰이는가?

운영 관점:
오류, 지연, 중복, 품질 문제를 어떻게 추적할 것인가?

서비스 관점:
최종적으로 대시보드, 알람, RAG 답변, 운영 리포트에 어떻게 연결되는가?
```

## 1.5 1단계에서 만드는 것

1단계에서는 완성된 기능을 만드는 것이 아니라, 이후 구현의 기준이 되는 **아키텍처 산출물**을 만든다.

24시간 과정에서는 모든 문서를 깊게 만들기보다, 이후 단계와 직접 연결되는 핵심 산출물을 우선 작성한다.
```text
1. 프로젝트 목적 보완
2. 사용자 역할 정의
3. 데이터 소스 정의
4. AI 서비스 데이터 유형 정의
5. RAG 문서 데이터 구조 정의
6. 피드백 로그 구조 정의
7. 서비스 로그 구조 정의
8. 도메인 이벤트 맵 작성
9. 이벤트 공통 필드 정의
10. 전체 데이터 흐름 정의
11. Raw / Staging / Mart 역할 정의
12. C4 Context 다이어그램 작성
13. C4 Container 다이어그램 작성
14. Mermaid 기반 데이터 흐름도 작성
15. 최종 시연 시나리오 정의
```

1단계에서 하지 않는 것은 다음과 같다.
```text
실제 Collector API 구현하지 않기

AI 모델 학습하지 않기
RAG 임베딩 생성하지 않기
WebSocket 대시보드 구현하지 않기
Prometheus/Grafana 설정하지 않기
Docker Compose 전체 통합하지 않기
```

### 2일차. 도메인, 데이터 소스, 데이터 흐름 설계 — 8h

#### 학습 목표

주니어는 산업안전 관제 플랫폼에서 어떤 데이터가 발생하는지 정의하고, Raw, Staging, Mart, Feature Dataset, Vector DB의 차이를 설명할 수 있어야 한다.

이론 3h
```text
도메인이란 무엇인가?
도메인 요소와 기능의 차이
사용자 역할과 데이터 발생 주체
데이터 소스란 무엇인가?
Raw 데이터란 무엇인가?
```

## 1.18 한 문장 정리

```text
1단계는 코드를 많이 작성하는 단계가 아니라,
AI 서비스가 사용할 데이터와 그 데이터가 흐르는 시스템 구조를 먼저 고정하는 단계이다.
```

반드시 기억해야 할 문장은 다음이다.

```text
AI 서비스는 모델만으로 완성되지 않는다.
AI 서비스는 데이터가 발생하고, 수집되고, 검증되고, 저장되고,
AI/RAG/대시보드/피드백/운영으로 이어지는 데이터 플랫폼 위에서 동작한다.
```

이 기준으로 1단계를 잡아두면 이후 2단계부터는 훨씬 자연스럽게 이어진다.

```text
1단계: 어떤 데이터를 다룰지와 전체 구조를 정의한다.
2단계: 그 데이터를 수집하고 Raw에 저장한다.
3단계: Raw를 Staging, Mart, Training Dataset으로 바꾼다.
4단계: 실시간 이벤트와 AI 판단 결과를 대시보드에 연결한다.
5단계: 데이터 품질, 계보, 거버넌스를 점검한다.
6단계: 안전 매뉴얼 문서를 RAG용 벡터 데이터로 만든다.
7단계: 피드백과 운영 로그를 재학습 후보 데이터와 DataOps 지표로 만든다.
```

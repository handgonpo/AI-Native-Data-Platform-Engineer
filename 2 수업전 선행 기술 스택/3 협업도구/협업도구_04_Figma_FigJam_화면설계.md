
> 역할: 화면 구조 설계와 팀 아이디어 시각화  
> 사용 시점: 대시보드 화면 설계, 발표 준비, 팀 아이디어 정리 단계  
> 핵심 목적: 데이터가 화면 어디에 표시되는지 시각적으로 정리한다.

---

## 1. Figma와 FigJam은 무엇인가?

Figma는 화면 설계와 UI 구조를 만드는 도구이다.  
FigJam은 팀 아이디어를 자유롭게 정리하는 화이트보드 도구이다.

수업에서는 둘을 깊게 디자인 도구로 배우기보다, 다음 목적으로 가볍게 사용한다.
```text
관제 대시보드 화면 구조 잡기
데이터 표시 위치 정리
사용자 흐름 정리
팀 아이디어 정리
최종 발표용 구조도 보정
```

---

## 2. Figma의 역할
```text
Figma = 화면 구조 설계
```

예를 들어 산업안전 관제 대시보드에서는 다음을 정리할 수 있다.
```text
센서 상태는 화면 어디에 표시할 것인가?
알람 목록은 어디에 둘 것인가?
작업자 위치 지도는 어디에 표시할 것인가?
위험도 색상은 어떻게 보여줄 것인가?
RAG 대응 매뉴얼 버튼은 어디에 둘 것인가?
운영자 피드백 버튼은 어디에 둘 것인가?
```

---

## 3. FigJam의 역할
```text
FigJam = 팀 아이디어 보드
```

다음 내용을 정리하기 좋다.
```text
팀 아이디어 브레인스토밍
기능 우선순위 정리
사용자 흐름 스케치
발표 흐름 정리
회고 의견 정리
```

---

## 4. Mermaid와 Figma의 차이

| 구분 | Mermaid | Figma / FigJam |
|---|---|---|
| 목적 | 기술 구조 문서화 | 화면과 발표용 시각화 |
| 위치 | Markdown, GitHub 문서 | 디자인/화이트보드 |
| 장점 | Git으로 변경 이력 관리 가능 | 보기 좋게 표현 가능 |
| 사용 예 | 데이터 흐름, 시스템 아키텍처 | 대시보드 화면, 발표 자료 |

수업에서는 다음 순서를 권장한다.
```text
1. Mermaid로 기술 구조를 먼저 정확히 작성한다.
2. GitHub docs에 저장한다.
3. 필요하면 Figma에서 발표용으로 보기 좋게 재구성한다.
```

## 6. 대시보드 화면 설계 시 체크할 것
```text
어떤 데이터가 화면에 표시되는가?
그 데이터는 어떤 API에서 오는가?
데이터 갱신 주기는 어떻게 되는가?
실시간으로 바뀌는 영역은 어디인가?
알람은 어떤 색상과 상태로 표시되는가?
사용자가 클릭할 수 있는 버튼은 무엇인가?
피드백은 어디에서 입력하는가?
```

## 7. 화면과 데이터 연결 예시

| 화면 영역 | 연결 데이터 | API 예시 |
|---|---|---|
| 센서 상태 카드 | 현재 센서값 Mart | `/api/dashboard/sensors` |
| 알람 목록 | 알람 Mart | `/api/alarms` |
| 작업자 위치 지도 | 작업자 위치 Staging/Mart | `/api/workers/location` |
| 위험도 그래프 | Risk Mart | `/api/risk/summary` |
| 대응 매뉴얼 | RAG 검색 결과 | `/api/rag/search` |
| 피드백 입력 | Feedback API | `/api/feedback` |

## 8. 수업에서 깊게 하지 않아도 되는 것

주니어 수업에서는 아래 내용까지 깊게 하지 않아도 된다.
```text
디자인 시스템
컴포넌트 라이브러리
오토 레이아웃 심화
프로토타입 애니메이션
고급 UI 디자인
색상/폰트 시스템 상세 설계
```

이 과정의 핵심은 예쁜 화면보다 **데이터가 화면 어디에 연결되는지 이해하는 것**이다.

## 9. 한 문장 정리
```text
Figma와 FigJam은 화면을 예쁘게 만드는 도구라기보다, 데이터가 사용자 화면에 어떻게 표시되고 어떤 흐름으로 사용되는지 시각적으로 정리하는 도구이다.
```

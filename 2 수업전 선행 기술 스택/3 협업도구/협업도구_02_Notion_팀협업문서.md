
> 역할: 팀 문서와 제출물 관리  
> 사용 시점: 팀 프로젝트 시작 이후  
> 핵심 목적: 팀원이 함께 봐야 하는 내용을 한 곳에 정리한다.

---

## 1. Notion은 무엇인가?

Notion은 팀 문서, 회의록, 표, 체크리스트, 일정, 링크를 한 곳에 정리할 수 있는 협업 도구이다.

수업에서는 Notion을 다음 용도로 사용한다.
```text
팀 회의록
역할 분담
프로젝트 개요
요구사항 정리
제출물 링크 모음
팀 일정
데일리 진행 상황
최종 발표 준비
```

---

## 2. Notion의 역할
```text
Notion = 팀 공식 문서 공간
```

Obsidian이 개인 정리라면, Notion은 팀원 모두가 함께 보는 문서이다.

---

## 3. Notion에 정리하면 좋은 내용
```text
팀명과 팀원
팀원별 역할
프로젝트 주제
요구사항
회의록
작업 현황
GitHub 저장소 링크
Jira 보드 링크
Figma 링크
최종 제출 자료
발표 자료 링크
```

---

## 4. 추천 Notion 페이지 구조
```text
팀 프로젝트 홈
├── 1. 프로젝트 개요
├── 2. 팀원 역할 분담
├── 3. 회의록
├── 4. 요구사항 정리
├── 5. 작업 현황
├── 6. 산출물 링크
├── 7. 발표 준비
└── 8. 회고
```

---

## 5. 역할 분담표 예시

| 이름 | 역할 | 담당 업무 |
|---|---|---|
| 주니어 A | 데이터 수집 | FastAPI Collector |
| 주니어 B | 파이프라인 | Raw → Staging 변환 |
| 주니어 C | 대시보드 | Django 화면 |
| 주니어 D | 문서/RAG | 매뉴얼 문서 정리 |

## 6. 회의록 템플릿
```markdown

## 날짜

## 결정된 내용

| 작업 | 담당자 | 마감일 | 상태 |
|---|---|---|---|

## 이슈 / 질문
```

## 7. Notion과 Jira의 차이

| 구분 | Notion | Jira |
|---|---|---|
| 목적 | 팀 문서 정리 | 작업 카드와 진행 상태 관리 |
| 단위 | 문서, 표, 회의록 | Issue, Task, Bug |
| 사용 예 | 요구사항 정리 | Raw 저장 기능 구현 |
| 장점 | 보기 좋게 정리 가능 | 진행 상태 추적 가능 |

---

## 8. 수업에서의 사용 원칙
```text
회의록은 Notion에 작성한다.
팀원 역할 분담도 Notion에 작성한다.
최종 제출 링크도 Notion에 모은다.
실제 작업 진행 상태는 Jira 또는 GitHub Issues로 관리한다.
코드와 README는 GitHub에 저장한다.
```

## 9. 한 문장 정리
```text
Notion은 팀원이 함께 봐야 하는 회의록, 역할 분담, 요구사항, 제출물 링크를 정리하는 팀 협업 문서 공간이다.
```
